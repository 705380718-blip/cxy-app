# 交付小助手 Windows 试运行包

版本：0.5.7 / windows-local-20261012。目标：Windows 11 x64、当前登录用户、普通权限。内置 Python 3.14.8 和 20 个锁定依赖，无需安装 Python，无需启动时联网安装组件。

本包已完成 macOS 上的共享逻辑回归与离线构建校验；Windows 原生启动、DPAPI、ACL、托盘及真实微信仍需按下表验收。尚未签名，不属于正式 Windows 发布版。

## 第一次使用

1. 对 ZIP 执行 PowerShell `Get-FileHash -Algorithm SHA256 文件路径`，与交付的 `.sha256` 文件比对；解压到自己的本地目录，保留全部子目录。勿直接在 ZIP 内运行。
2. 双击 `04-self-test.cmd`。会使用临时构造数据、模拟模型运行全链路，并在桌面生成 `wechat-windows-self-test.json`。不会采集微信或调用真实模型；结果须为 `passed`、`mode` 须为 `windows-native-offline`。
3. 双击 `01-start.cmd`，默认端口 8791。浏览器打开本机一次性入口，点击“进入交付小助手”。入口 5 分钟内有效。以后同一浏览器会话直接打开工作台；入口过期或换浏览器时，先 `02-stop.cmd` 再启动。首次重定向若出现登录提示，点击“刷新工作台”。
4. 按“微信与群聊 → 采集规则 → 开始采集 → AI 分析 → 信息与报告”操作。当前没有已验证的 Windows 微信版本配置，实时采集会明确阻断；可先选 TXT/CSV 导入完成业务试用。
5. 右上角设置中填写自己的 DeepSeek Key；确认自动整理授权后，新消息会自动分析并进入结果页。历史数据仍需明确选择并分析；旧建议和人工修改冲突按页面提示处理。真实模型调用会向配置服务发送脱敏文本并可能产生费用。
6. 托盘可打开工作台、停止程序、重新启动、停止并退出托盘。关闭浏览器不会停止后台。程序重启后在“开始采集”检查采集状态；未通过微信适配校验时仍不会采集。

包目录仅含程序。数据、配置、日志和钥仓位于当前用户的 `%LOCALAPPDATA%\GroupChatOrganizer`。端口等配置在 `config\runtime.env`，服务运行中修改后须停止再启动。不支持将业务库或私有文件配置到该目录之外。端口占用不会杀掉其他程序；请更换端口。

PowerShell 策略或企业管控拦截时，保留报错交管理员按组织政策处理；启动脚本不修改执行策略、不申请管理员权限、不关闭杀毒。校验脚本用于检测损坏或误改，不能替代外部 ZIP SHA 校验、数字签名或受信分发。

## 旧 Windows 版本复用

停止旧 wxauto 工具，完整备份旧目录（含 SQLite 的 WAL/SHM），再运行 `05-export-legacy.cmd`，输入旧业务数据库路径。工具只读旧库，在当前用户私有目录下创建新的导出目录，绝不覆盖旧数据。

按 `export-index.json` 的群名映射，在新版对应群来源导入 CSV。相同来源下保留稳定消息标识，重复导入不会产生新记录。旧版已复核问题和历史汇总另存 `legacy-review-history.json`，未自动变成新版任务，避免语义误转换；旧版原目录需继续保留供查阅；legacy-message-map.json 保留旧消息 ID 与导入消息标识的对应关系。CSV 保留聊天原文，只用于应用导入，不要把不可信聊天文本直接作为 Excel 表格打开。不要把导出文件发到聊天或公开仓库。

## 真实微信适配

运行 `03-diagnose-and-key-prep.cmd`，首先生成桌面的 `wechat-windows-diagnostic.json`，仅包含版本、布局等诊断元数据，不含密钥/正文/账号名。没有已验证 profile 时回车退出，**不要自行把模板 enabled 改为 true**。

已验证的新 profile 应放在用户数据目录 config 下，并通过 runtime.env 的 WML_WINDOWS_PROFILES_PATH 指定，或领取重新生成的完整包；不要改动包内文件后绕过完整性校验。

真实适配需要 Windows/微信精确版本与构建号、数据库布局/表结构、可验证的数据库密钥提供方式，以及 DB/WAL 真实样本验证。当前工具只支持用户明确提供候选密钥后的验证与 DPAPI 保存，不包含自动扫描微信进程内存取钥功能。需要以上环境证据后才能生成支持该版本的 profile；这不是勾选设置就能完成的测试。API Key 只在本机设置输入，候选数据库密钥只在本机授权工具处理，勿发送给他人。

## 交给真机执行的验收表

| 项目 | 操作与通过标准 |
|---|---|
| 干净系统 | 未安装 Python 的 Windows 11 x64 上自检通过，记录系统版本和架构；ARM64 不在本包范围 |
| 路径与安装 | 中文、空格路径以及程序目录只读时可启动，数据只写用户目录 |
| 首次登录 | Edge/Chrome 的本地表单→工作台可登录；无 Cookie 请求业务 API 为 401；重启后旧 Cookie 失效 |
| 多用户与ACL | 自检完成 DPAPI 往返；另一个普通 Windows 账号读不到用户私有目录及钥仓；检查当前 SID 独占权限 |
| 生命周期 | 重复启动只打开原实例；双开、过期PID、被占用端口不误杀；停止后端口释放，配置/结果保留 |
| 托盘 | 打开、停止、重新启动、退出可用；睡眠唤醒后队列状态可恢复，无重复任务 |
| 旧数据 | 原库不变；CSV 导入数量匹配、二次导入去重；旧复核/汇总仍可查阅 |
| 业务闭环 | 配置群与规则→构造文本导入→授权自动整理→查看结果→撤回/恢复→报告 Markdown/CSV，先用自检再真实试用 |
| 微信兼容 | 仅在精确profile通过后：登录/退出、多个账号选择、重启微信、升级阻断、群名变更、@识别、重复消息、DB/WAL一致性验证 |
| 模型质量 | 用获准样本检查全部成员明确待办；区分普通询问、事实、已完成事项和真正待办，记录误报漏报 |
| 稳定性 | 连续 24 小时、断网恢复、模型超时/限流、重启中断；记录消息数、队列、内存和错误，不预填成绩 |
| 升级与回滚 | 停止后备份整个用户数据目录；新包另目录启动。同schema保留数据，高版本库拒绝旧程序；降级须恢复对应备份 |
| 清理与卸载 | `02-stop.cmd` 后删除程序目录保留数据；`06-clear-tool-data.cmd` 需输入 DELETE 才删本工具数据，不动微信目录 |
