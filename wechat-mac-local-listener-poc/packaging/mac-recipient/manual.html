1. 安装与首次使用

条件说明
电脑Apple Silicon（M 系列）Mac。“苹果菜单 → 关于本机”可查看芯片和系统。Intel 不适用。
系统内置运行时最低为 macOS 11；微信自身可能要求更高系统。菜单会显示实际版本，本构建未覆盖所有系统版本实测。
运行环境包内已带 Python 3.11.15 和全部运行依赖，不需要安装 Python、Homebrew 或开发工具。日常启动不下载依赖。
空间与网络首次准备微信副本需至少 3 GB 可用空间。文件导入、规则整理、报告可离线；微信登录和 AI 分析需要网络。
  1. 完整解压 ZIP，将整个文件夹放到本机可写目录，如“文稿/交付小助手”。不要从压缩包预览中运行，也不要只复制启动文件。
  2. 双击 start.command，会打开中文终端菜单。不要移动或删除包内的 python、app、tools 目录。
  3. 输入 1 检查环境；成功会显示 macOS、Python、微信版本与采集配置状态。
  4. 输入 2 完成首次配置。可选“仅使用聊天文件导入”或“配置本机微信监听”。
  5. 输入 3 启动并自动打开浏览器。默认地址为 http://127.0.0.1:8792/，以菜单实际输出为准。

服务在后台运行，关闭菜单终端或浏览器不会停止它。需要停止时，再次双击 start.command，选择 4。不自动开机启动；重启电脑后需重新启动服务，并在网页点击“开始采集”。

2. 配置本机微信监听

这是本机非官方采集方式。只处理你本人有权访问的群聊。首次准备涉及临时微信副本和进程内密钥获取；日常监听读取本机数据库副本。软件没有官方全版本兼容承诺。

2.1 查看版本与账号

先在官方微信登录，打开准备监测的测试群，再关闭本工具服务。菜单选择“首次配置 → 配置本机微信监听”。工具列出本机账号目录供你选择，不会在多账号时自行猜测。

微信版本 / 构建本包处理方式
4.1.11.55允许进入配置，仍须在本机完成密钥和数据库验证。
4.1.12 / build 269341只接受对应构建；仍需接收方验证新消息。
4.1.13 / build 269629只接受对应构建；仍需接收方验证新消息。
4.1.15 / build 270115本版新增的待实机验收构建。允许进入首次准备，必须通过本机全部数据库及消息结构校验；没有本机验证记录时不能启动采集。
其他版本或构建暂停采集配置，可使用导入模式并向发布者反馈版本。不需要降级微信或关闭系统保护。

4.1.11.55—4.1.13 来自历史本机记录。4.1.15（270115）由接收者截图确认版本，发布者尚未取得此构建的真实数据库验收结果；是否兼容须以本节校验及第 5 节测试群验收为准。

2.2 选择密钥准备方式

已有本人密钥：选择“导入自己已有的微信密钥 JSON”，在文件选择窗口选择该账号的密钥文件。工具只接受联系人和全部消息分片都可验证的文件，不能使用他人的密钥。

首次准备：手动退出官方微信（⌘Q），选择“在此电脑首次准备”。阅读说明后输入 YES。工具复制并临时签名微信副本，在副本启动前装入采集钩子，仅收集所选账号数据库对应的派生密钥。

  1. 等待临时微信副本打开；按客户端要求完成登录，打开需要监测的群。
  2. 终端显示“已验证 X / Y 个数据库”，最长等待三分钟；不要把等待过程误认为已成功。
  3. 工具仅在全部必要密钥、解密副本完整性和数据库结构验证通过后保存配置。失败会明确说明，不会假装开启采集。
  4. 结束后临时副本自动关闭并删除；重新打开“应用程序”中的官方微信。
  5. 启动本工具，在网页配置精确群名、本人昵称，然后点击“开始采集”。

工具不会改动官方微信应用、强制退出官方微信、关闭 SIP/Gatekeeper 或要求管理员密码。若副本无法启动或系统拒绝准备操作，按故障排查反馈；不要反复关闭系统保护。

日常解码每轮检查版本与各分片密钥。微信更新、换账号或新增分片后，如果校验失败，应停止服务、重新配置；没有覆盖的版本等待适配。

3. 日常使用

  1. 微信与群聊：新建整理空间；填写群的完整名称和自己的昵称。多个群按页面提示输入；同名群无法唯一定位时应先消除歧义。
  2. 采集规则：设置关键词、关注人员、@我规则和消息保留天数。首次历史窗口默认 7 天，只有本机已有的聊天记录可以读取。
  3. 开始采集：点击开始，观察状态和最近消息。微信需正常登录；电脑睡眠、关机或服务停止期间不实时采集。恢复后的补采受本机历史、留存窗口和密钥可用性限制。
  4. AI 分析：可选功能，按下一节配置；未配置 AI 时可导入、按规则整理、手工建立事项与生成报告。
  5. 信息与报告：核对原文、采纳事项并更新进展；选择日期生成报告，导出 Markdown 或 CSV。AI 结果不等于人工确认，也不代表事项已完成。

当前重点支持文本与结构化引用文本；图片显示占位，不提供图片识别、语音转写或文件正文提取。默认保留 7 天，过期清理会影响关联结果与报告；已导出的文件和备份由使用者自行管理。

使用文件导入

菜单选择 5 生成当天的构造 TXT/CSV 样例；网页切换为导入来源，先预览再确认。TXT 与 CSV 二选一，不要把同一内容的两种格式重复导入。单次限 2 MiB / 2000 行。

[当天日期 09:00:00] 构造同事甲: 我负责今天补齐拓扑并提交。

TXT 以实际的 YYYY-MM-DD HH:MM:SS 替换示例日期；CSV 为 UTF-8，表头 source_message_id,timestamp,sender,content。历史日期需覆盖在配置的留存窗口内。

备份与恢复

先选菜单 4 停止服务，再选 6 备份。备份包含业务库、采集配置、微信密钥和模型配置，文件权限仅当前用户可读；不是加密备份，不要外发或放进公共同步目录。需跨设备保管时，请由自己使用可信加密方式保存。

恢复时选择 7，选择本工具备份，确认后执行。工具先核对路径、哈希、版本及数据库完整性，再自动备份当前状态并替换。格式不匹配时不会恢复；失败会保留或回退原状态。当前接受本构建及 2026-11-05 接收方包的备份，且数据库版本不能高于本程序。恢复会保留备份中的 AI 开关，启动前应确认原自动分析设置仍符合你的意图。未来版本需要迁移验证。

升级与旧包迁移

  1. 停止旧服务，先备份，保留旧包和校验文件。
  2. 本接收方版升级：解压新包到新目录；数据目录独立于软件，勿删除数据目录。首次启动前检查新版本兼容说明。
  3. 从旧 wechat-delivery-offline-0.5.x 包迁移：停止旧包，菜单选 9，选择含 runtime/data/delivery.db 的旧解压目录。工具复制业务库和模型配置；当前已有业务库时拒绝覆盖。
  4. 迁移后重新完成微信采集配置；AI 会暂停，请核对模型与自动分析范围后自行启用。
  5. 源码开发版及其他历史 App 使用不同数据路径，不能直接使用菜单 9；请向发布者确认迁移方案。

数据库升级后不要直接用旧程序打开；回退应停止新版本，使用升级前备份配合原版本。旧导出文件不会自动迁移或删除。

7. 打不开或收不到消息怎么办

现象处理
系统提示无法验证开发者 / 阻止打开先核对发布者与 ZIP 的 SHA-256。依照 macOS“系统设置 → 隐私与安全性”中当前文件的允许打开提示操作；该选项随系统版本变化。可参考 Apple 官方说明。不要关闭系统整体安全保护。
命令没有执行权限终端输入 chmod +x （末尾空格），将 start.command 拖入终端，回车后重试；不要修改其他目录权限。
内置 Python 被隔离，无法运行确认文件来自可信发布者且 ZIP 校验一致后，可由本人在终端输入 xattr -dr com.apple.quarantine （末尾空格），将本软件解压文件夹拖入再回车。仅限该文件夹，不作用于整个系统。管理策略禁止时请联系管理员或发布者，不绕过策略。
“不支持架构” / Bad CPU type确认是 M 系列并使用原生终端，没有勾选通过 Rosetta 打开；Intel 不能使用该包。
缺少 Python / 文件找不到此包已内置运行时；请重新完整解压，核对文件是否被移动、隔离或清理，不要另装不匹配的 Python 覆盖它。
端口占用菜单选择 8 改为 8794 等独立端口，再启动。不会自动结束其他应用；5173 / 8000 不可选。
找不到微信账号 / Operation not permitted检查官方微信是否登录和安装位置。仅当系统明确拒绝文件访问时，按系统提示给运行菜单的终端授予所需访问权限；单位设备先遵循管理策略。
版本不在列表 / 缺少分片密钥停止服务，核对版本，重新配置。未知版本使用导入模式，提供脱敏诊断等待适配。
密钥准备超时 / 副本打不开确认官方微信已自行退出、所选账号正确、空间充足；副本登录后打开测试群。未成功前不启用采集；用菜单 10 导出脱敏诊断，其中会记录失败阶段。不要向别人发送密钥文件或聊天库。
网页可打开但没有新消息核对群完整名称、同名群、官方微信登录、开始采集按钮、版本与密钥提示、保留天数；发送新的唯一编号文本验收。
AI 没有结果 / 分析失败确认模型已启用、Key 和网络可用、额度及预算足够、来源范围正确、已同意发送；检查队列状态。AI 问题不代表本机采集一定失败。
菜单提示另一个工具正在运行关闭先前打开的菜单后再试。退出菜单不会结束后台服务。

ZIP 校验：终端输入 shasum -a 256 后拖入 ZIP，比较输出与随附 .zip.sha256 的摘要。不要从来历不明的消息复制整段终端命令。

8. 卸载与问题反馈

仅移除程序：先从菜单停止服务，再把解压的软件文件夹移到废纸篓；数据和备份仍保留。

同时移除本工具数据：确认已经保管所需备份后，Finder“前往 → 前往文件夹”输入上面的 Application Support 路径，把该文件夹移到废纸篓；其中包括本工具复制的微信密钥、AI 配置、解密副本与备份。自己另存的导出、外部备份和原始密钥文件需要分别处理。不要删除微信官方数据目录。

反馈：菜单 10 生成 diagnostic.json，不含账号、路径、聊天和密钥。把它连同“哪一步失败、界面提示、发生时间”发给给你软件的人。截图应遮挡群名和正文；不要发送业务数据库、完整服务日志、微信密钥或 AI Key。支持联系人由发布者在发送消息中提供。
