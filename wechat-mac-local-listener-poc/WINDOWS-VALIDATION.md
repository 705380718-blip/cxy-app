# Windows 微信本地监听 POC 真机验收单

## 1. 测试边界

- [ ] Windows 10/11 x64 测试机，不使用生产办公主机。
- [ ] 自有测试账号、已告知测试群、测试消息不含客户隐私。
- [ ] 记录微信 exe 名、file version、build、安装来源和系统版本。
- [ ] Defender/EDR 如有阻断，只记录告警，不关闭或绕过组织策略。

## 2. 观察与诊断门禁

- [ ] 运行 `1-首次密钥准备.cmd`，成功生成桌面诊断 JSON。
- [ ] 确认 JSON 的 `contains_keys/chat_content/account_name` 都为 `false`。
- [ ] 单账号自动选择；多账号必须设置 `WML_WINDOWS_ACCOUNT_ID` 后才继续。
- [ ] 页面能显示 DB、WAL、SHM 数和布局指纹；未知 build 显示“观察模式”。
- [ ] 在未启用 exact profile 时，业务库不会出现真实微信消息。

## 3. 密钥与 schema 门禁

- [ ] 候选 provider 由用户主动运行，不常驻，不要求绕过 EDR。
- [ ] contact、索引（若该 build 使用）和至少一个 message DB 分别通过页 HMAC。
- [ ] 所有解密副本 `PRAGMA quick_check=ok`。
- [ ] 关键联系人/成员/群/消息表列与 profile 一致。
- [ ] 解密后 schema fingerprint 与 enabled profile 完全一致。
- [ ] DPAPI blob 仅当前 Windows 用户可解密，另一普通本机账号失败。
- [ ] `icacls %LOCALAPPDATA%\GroupChatOrganizer` 只显示当前用户和必要系统主体。
- [ ] 日志、API、页面、诊断和崩溃输出中搜索不到候选密钥片段。

## 4. 原库只读证明

- [ ] 启动前记录微信 DB/WAL/SHM 的路径、size、mtime 和哈希抽样。
- [ ] 监听期间微信能正常聊天、发图、语音通话和退出/登录。
- [ ] 工具未创建微信目录内的新文件，未主动改变原 DB/WAL/SHM mtime。
- [ ] 工具停止后没有残留打开原库的进程句柄。

## 5. 历史与增量对账

- [ ] 首次指定群只导入当前本地实际存在的最近 7 天消息。
- [ ] 文本、引用、图片占位分别抽样与微信界面对账。
- [ ] 发送 `WIN-POC-001` 至 `WIN-POC-100`，记录发送/入库时间。
- [ ] 100 条编号消息 0 漏失、0 重复、同群顺序一致。
- [ ] 稳态延迟 P95 ≤ 2 秒，P99 ≤ 5 秒。
- [ ] 引用正文只用于展示，不因被引用问题文本重复生成问题。
- [ ] 未支持类型显示占位，且不进入待复核问题库。

## 6. 恢复和轮换

- [ ] 工具启动/停止 3 次，高水位和去重正常。
- [ ] 微信退出/启动 3 次，恢复后不重导、不漏新消息。
- [ ] Windows 重启 3 次，业务库和历史标记仍有效。
- [ ] 覆盖一次 WAL checkpoint；WAL 消失/重建仍触发正确读取。
- [ ] 覆盖一次消息分片切换；新分片被发现且旧消息不重复。
- [ ] 让密钥或 schema 故意失效，系统进入阻断而不是生成空报告。

## 7. 业务闭环

- [ ] 多群白名单、本人昵称、指定人员、关键词保存生效。
- [ ] 待复核逐条和批量确认/忽略均持久化。
- [ ] 消息检索、分页、引用展示、图片占位正确。
- [ ] 单日和跨日时间段报告内容均可追溯到原消息。
- [ ] 修改留存天数后立即删除过期业务消息及关联问题。

## 8. 24 小时与清理

- [ ] 连续运行 24 小时，记录 WAL 事件、解码错误、P50/P95/P99 和磁盘占用。
- [ ] 磁盘不足时显示明确阻断，不写微信原库。
- [ ] 停止脚本只结束 PID 记录对应的本工具进程。
- [ ] 清理脚本只删除 `%LOCALAPPDATA%\GroupChatOrganizer`。
- [ ] 清理后业务库、密钥 blob、快照、日志、配置和 PID 均不存在。
- [ ] 微信安装与账号数据仍完整可用。
